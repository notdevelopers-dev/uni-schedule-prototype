# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Обовʼязкові правила проєкту

- **Сайт неофіційний.** Жодних згадок назви університету, його логотипа чи іншої символіки в інтерфейсі, README, метаданих
  і коментарях: використовувати таке заборонено, і сайт не має виглядати офіційним. Назва застосунку — «Розклад пар».
  Позначка «неофіційний» (`UNOFFICIAL` у `site/js/ui/schedule.js`) має лишатися на першому екрані, у підвалі розкладу й у налаштуваннях.
  Винятки — лише те, без чого не працює: адреса експорту в збирачі й дані з експорту (назви груп, факультетів).
  Внутрішні ключі `lnu-rozklad:*` у localStorage і формат `lnu-rozklad-bundle/1` не перейменовувати: це зітре збережені налаштування користувачів.
- **Мінімум запитів до деканату.** Це чужий сервер. Сайт ніколи не звертається до нього напряму, лише до `data.json`.
  Будь-яка зміна збирача не повинна збільшувати кількість запитів: не повторювати `-8` і помилки деканату, не прибирати кеш
  списку груп, не робити запусків частіше без потреби. Нові дані — краще одним ширшим запитом, ніж кількома.
  Для перевірок — мок `scripts/mock-dekanat.mjs` (див. команди), а не реальний сервер.

## Команди

Без npm, залежностей і кроку збирання. Потрібен Node 22+.

```sh
node --test                                        # усі тести (tests/*.test.mjs)
node --test tests/data.test.mjs                    # один файл
node --test --test-name-pattern="buildBundle"      # тести за назвою
python3 -m http.server 8000 -d site               # сайт локально (ES-модулі не працюють з file://)
# http://localhost:8000/?now=<дата в межах знімка>T10:40 — «перевести годинник» для перевірки поточної/наступної пари

node scripts/mock-dekanat.mjs &                    # мок деканату на :8765 з даними site/data.json; CODE=-8 — відповідати кодом
ENDPOINT=http://127.0.0.1:8765/ OUT=/tmp/out.json node scripts/fetch-schedule.mjs   # збирач на моку; мок логує кожен запит
```

Лінтера чи форматера немає — стиль підлаштовувати під навколишній код (2 пробіли, одинарні лапки, крапка з комою).
Інтерфейс, коментарі в коді й README — українською.

## Архітектура

Статичний сайт у `site/` (публікується на GitHub Pages workflow `pages.yml` при пуші в `main`) + збирач даних.

**Потік даних:** `scripts/fetch-schedule.mjs` (щотижня, `update-schedule.yml`) → `site/data.json` → `StaticRepository` → екрани.
Збирач комітить `data.json` у `main` від імені бота й сам запускає `pages.yml` (пуш з `GITHUB_TOKEN` інших workflow не запускає).
Тому перед пушем у `main` треба підтягнути свіжий `main`: там можуть бути коміти бота з даними.

**Шари сайту (`site/js/`):**
- `data/` — джерела даних з одним асинхронним інтерфейсом (`getMeta`, `listGroups`, `getGroupSchedule`, `getRoomSchedule`,
  `getTeacherSchedule`, …). `static-repository.js` читає `data.json`, будує індекси груп/аудиторій/викладачів (`buildIndex` — чиста функція),
  а розклади аудиторій і викладачів отримує *інвертуванням* групових розкладів. `api-repository.js` — ескіз майбутнього бекенду;
  перемикання в `config.js`. `psrozklad.js` — розбір формату експорту й кодів помилок (`exportStatus`, прапорець `keepPrevious`).
- `domain/` — чисті функції без DOM: `parse.js` (викладач з посадою, аудиторія з префіксами №/N, шифр групи), `lessons.js`
  (нормалізована модель `Lesson` зі стабільним `id`, `mergeAcrossGroups` для потокових пар), `electives.js` (фільтр «мого розкладу»:
  підгрупи, «Збірна група» = іноземна / дисципліна з кількома викладачами / ДВВС).
- `ui/` — екрани на власному мінімальному `h()` з `dom.js`; `schedule.js` — спільний рендер дня, тижня (список на телефоні,
  сітка «дні × пари» від 960 px — обидва рендеряться, CSS показує один), карток пар і підвалу. Маршрути — у hash (`#/my`, `#/rooms/…`),
  тому сайт працює в підкаталозі; всі шляхи відносні.
- `main.js` — точка входу: завантажує дані, тримає стан (`prefs`, `ui`) і передає екранам `ctx`.

**Кольори й теми:** кожен колір — токен на початку `site/assets/app.css` у вигляді `light-dark(світлий, темний)`; компоненти беруть
лише `var(--…)`. Тему визначає `color-scheme`: на `:root` — `light dark` (як у системі), вибір користувача `theme.js` ставить на `<html>`,
а скрипт у `<head>` `index.html` — ще до відмалювання. Не додавати `@media (prefers-color-scheme)` і не дублювати темні значення:
інакше ручний вибір теми перестане на них діяти. Свідомо підтримуються лише браузери з `light-dark()` (2024+).

**Формат `data.json`:** приймається сирий експорт деканату, масив експортів або пакет `lnu-rozklad-bundle/1`
(`range`, `lists.group`, `lists_fetched_at`, `schedules[]` з сирими відповідями). Збирач пише пакет; `lists.group` містить лише
потрібні групи, тож сайт вважає покриття повним. Особливості експорту (усе рядки, від'ємні ID, `group` — склад учасників, а не назва групи,
бронювання `reservation` без викладача й аудиторії) описані в README, розділ «Припущення щодо даних».

**Збирач** (`scripts/fetch-schedule.mjs`) перевикористовує з сайту лише `lib/` і `exportStatus` з `data/psrozklad.js`. Чисті функції (`buildBundle`, `reusableGroupList`, `filterGroupList`, `sameContent`, …) експортуються й тестуються в
`tests/fetch-schedule.test.mjs`; мережа — лише в `main()`. Коди `-2/-3/-8/-70` і збої не перезаписують попередній розклад групи,
`-4` — це «пар немає». Якщо зміст не змінився (без урахування часу збору), файл не переписується.
